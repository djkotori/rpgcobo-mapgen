# Castle map specification

## 設計方針

`castle`は、守備・補給・政務のために組み立てた城郭を生成する。
`town`の「用途と共有空間を先に決め、動線を確保してから建物と地面を整備する」
設計と、`TownPaving.cpp`の接続された舗装工事を利用する。

基本の空間順序は次のとおり。

```text
外部 → 堀の橋 → 正門・門楼 → 外郭の集結/補給空間
                               ↓
                             内門
                               ↓
                 主城入口 → 謁見の間 → 玉座
                              ├ 私室
                              ├ 宝物庫
                              └ 執務・生活の部屋
```

入口は南側を基本とし、追加の外門は他の城壁面へ配置する。内郭には入口を一つだけ設ける。
軍事型の内門は主城の扉から横にずらし、門を抜けてもすぐ直進できない経路にする。
宮殿型では正門・内門・主城の中央ホールを同じ軸にそろえる（丸めによる1セル差は許容）。

## 外形の決め方

城の外形を1セルごとのノイズで揺らさず、長い城壁面と隅の切り戻しから作る。
城壁と城下は画像サイズを全面利用し、外周に黒いマージンを設けない。外壁は堀幅だけ
画像端から内側に置き、門から画像端まで橋と進入路を通す。seedで隅の切り戻し寸法を変える。

隅の切り欠きのうち堀ではない外側は、アーキタイプに対応する単色地形で埋める。

| archetype | 切り欠き外の地形 |
|---|---|
| `concentric` | 平地（0） |
| `hill` | 山地（3） |
| `river` | 河川（7） |
| `palace` | 森（2） |
| `fortress` | 砂地（1） |

| castleMode | archetype | 空間上の制約 |
|---:|---|---|
| 0 | `concentric` | 四隅を切り戻した外郭と、主城を囲む内郭の二重構成 |
| 1 | `hill` | 奥の両隅を大きく削り、尾根の上部へ向かって狭まる外形。主城は奥側 |
| 2 | `river` | 西側の河川に面する隅を強く切り戻した非対称の外郭。川は西の外縁を通る |
| 3 | `palace` | 小さな隅切りと幅広い主城。儀礼の中央軸と高めの舗装率 |
| 4 | `fortress` | 前方の大きな隅切り、強い隅塔、ずらした内門による防御構成 |

形状から内外への距離を計算し、内側に城壁、外側に一定幅の堀を作る。
隅の切り欠きにはseed固定の低周波な揺らぎを加え、自然地形との境界が完全な直線に
ならないようにする。セル単位の白色雑音は使わず、斜めの隅でも城壁と堀の連続性を保つ。
川を城の内部へ描いてから消す処理は行わない。
`hill`は尾根に制約された平面構成のモデルであり、標高の物理計算や3Dの段差ではない。

塔は固定座標へ押し込まず、四隅・城壁面の防衛位置に最も近い、配置可能な場所を探す。
主城・内郭・門・他の塔を避け、すべての塔内部と階段に到達できるようにする。
4〜12基を扱い、塔数に関係なく配列外アクセスしない。

## 生成の依存関係

1. seedから国の裕福度を決め、アーキタイプと城の外形を選ぶ。
2. 城壁と堀の保護マスク、城壁上の見回り通路を作る。
3. 大通りの大門・大門楼と、小道の通用口・通用門楼を配置する。
4. 主城と内郭の場所を予約し、残った城壁面へ塔を配置する。
5. 主城を中央の公的な部屋列と、その両側の私的な部屋へ分割する。
6. 内門を開け、大門から主城までの主要経路を先に確保する。
7. 外郭の西寄りに訓練・集結の庭、東寄りに補給・馬のための庭を予約する。
8. 用途ごとに配置候補を評価して施設を建て、その用途の庭へ扉を向ける。
9. 塔・施設・門・庭を道路グラフで接続する。
10. 内郭の静かな側面に庭園、主城の背後に貯水槽を設ける。
11. 裕福度に応じて内装と舗装を整備し、実際の増築内容から築城履歴を作る。
12. 品質評価から最良候補を採用する。

施設は兵舎、厩舎、倉庫、厨房を必須の最初の4用途とする。
追加施設は礼拝堂、工房、衛兵所、作業棟。
兵舎・衛兵所は訓練場、厩舎・倉庫・工房は補給の庭、厨房・礼拝堂は主城側への近さを
配置コストに使う。空き地へ置いた後で用途を割り当てることはしない。

主城には入口ホールと玉座をそれぞれ一つだけ置く。部屋が多い場合はその間に謁見の間を
追加する。側室の扉は中央ホールと実際に接している壁へ配置する。隣の部屋と分割位置が
一致しない場合も、壁の交点へ扉を置かない。4〜32室の任意の整数を指定できる。

道路は既存の道を新規の空き地より低コストで通る。追加接続は全ノード対の割合ではなく、
ノード数の割合で上限を決めるため、大きな城が細い格子道路で埋まることを抑える。
門・部屋の扉・施設の床は後から道路や舗装で上書きしない。

## 裕福度と築城履歴

`countryWealth`は国の裕福度で、0.7〜2.5（1.0が通常）を取る。候補生成前にseedから一度だけ
決定するため、同一生成内の全候補で共通し、同じseedなら再現される。`-p countryWealth=値`
または短縮形`-p wealth=値`で固定でき、範囲外は0.7〜2.5へ制限する。

| 範囲 | `wealthClass` | 生成への影響 |
|---:|---|---|
| 0.70〜0.89 | `strained` | 施設・部屋・塔・家具・舗装を減らす |
| 0.90〜1.14 | `ordinary` | アーキタイプの標準構成 |
| 1.15〜1.64 | `prosperous` | 増築と舗装を段階的に追加 |
| 1.65〜2.14 | `wealthy` | 商業・軍事施設、塔、広い大通り、密な内装を追加 |
| 2.15〜2.50 | `opulent` | 最大5セル幅の大通り、豪華な内装、防御改修を追加 |

明示した部屋・施設・塔・門の個数範囲、`mainRoadWidth`、`pavingRatio`は裕福度による自動調整より
優先する。96未満では敷地容量を優先し、裕福度が高くても個数を4〜6、幹線幅を最大3セルに抑える。
高裕福度の追加施設はアーキタイプ別の商業施設と軍事annexを交互に建てる。裕福度1.5以上では
主城に内扉で接続した翼棟を1棟、2.15以上では左右2棟を追加し、主城の外形にも増築を反映する。
さらに主城左右の上郭へ大型の行政・宿泊・軍事棟を優先配置し、残余区画へ城型別の酒場、
ギルド、宿屋、専門施設、小公園、街路樹を加える。高裕福度では中庭を小さくし、建物間隔を
詰めることで未利用地を抑える。

`castleHistory`には、実際に生成できた構造から`foundation`、`keep_construction`、
`bailey_development`を記録する。裕福度や防御段階に応じて`economic_expansion`、
`defensive_modernization`、`interior_refit`を追加し、各段階に増築数と保守状態を持たせる。
`castleDevelopmentModel`は`wealth_and_construction_history_v1`。

## 城壁・門・監視設備

`outerWallDefenseStrength`は裕福度と独立した0.0〜2.0の外壁防衛力である。未指定時はseedから
独立に決まり、`-p outerWallDefenseStrength=値`または`-p outerDefense=値`で固定できる。

| 外壁防衛力 | 外郭 |
|---:|---|
| 0.0〜0.49 | 開放型。堀、外壁、外門を設けない |
| 0.5〜1.10 | 堀なしの乾式外壁と簡素な門 |
| 1.1超〜1.49 | 堀なしの外壁に壁上通路、門楼、監視塔を追加 |
| 1.5〜2.0 | 堀・外壁に壁上通路、門楼、監視塔を追加 |

既定の一様分布では、外壁あり・堀なしは全体の50%、堀ありは25%となる。

強化外郭では外壁厚の内側1〜2層を壁上専用tile `CASTLE_WALL_WALK`とし、歩行可能な`wall_walk`を設ける。
外壁に隣接する地上通路ではなく、`castleDefenseMask=2`を維持した城壁そのものの上面である。
防御段階4以上または裕福度1.6以上では幅を2セルとし、各門楼の`wall_access`から到達できる。
第一門は`main_gate` / `great_gatehouse`で、
裕福度に応じた大通り幅の橋と開口を持つ。追加門は1セル幅の`postern_gate` /
`postern_gatehouse`とし、小道へ接続する。

型別の基本防御段階はpalace 2、river 3、concentric/hill 4、fortress 5。
防御段階4以上の96px以上の城には、隅塔に加えて型別の監視塔を最低1基置く。
`castleWallForm`は各型3種類からseedで選び、切り戻しの非対称性とPlan上の形式名を変える。

## 舗装

`ApplyTownPaving`へ城の施設・主城・庭園の用途を渡す。
主要動線沿い、施設前の広場、通常道路沿いを優先し、道路につながる工事単位で整備する。
市松模様や座標の剰余で地面色を変える処理は使わない。

- 既定の`pavingRatio`: 宮殿型0.88、その他0.68を基準に、裕福度で0.35〜0.96へ調整。
- 対象は通常地面。建物内部・庭園・堀・訓練場・補給の庭は対象外。
- 0なら舗装しない。1なら接続可能な対象地面をすべて整備する。
- 最後の工事を途中で切らないため、実測値は目標を少し超える場合がある。
- `pavingTargetRatio` / `pavingActualRatio` / `pavingModel` / `pavingStages`に実績を出力する。

## サイズと指定パラメータ

CLIの対応サイズは64〜1024。小さな城では4施設・4室・4塔の最低構成を優先する。
96未満では隅切りと大きな共有の庭を省き、112未満では内郭を省く。
それ以上では、切り欠きや既存構造に接触しない範囲で主城との間隔を調整し、最大の内郭を作る。
大きな城では施設・部屋・塔の既定数を増やす。明示された数の範囲は上書きしない。

| パラメータ | 既定値・制約 |
|---|---|
| `castleMode` | 0〜4。未指定時は通常の候補群で5種類を比較 |
| `countryWealth` / `wealth` | 0.7〜2.5。未指定時はseedから決定 |
| `outerWallDefenseStrength` / `outerDefense` | 0.0〜2.0。裕福度と別のseed系列から決定 |
| `candidateCount` | 通常6、小規模では未指定時12。指定可能範囲1〜12 |
| `keepWidth`, `keepHeight` | 型・サイズ別。16〜外郭内部寸法の半分に制限 |
| `gateCountMin/Max` | 1..3 |
| `towerCountMin/Max` | 標準4..8。大型で6..10、8..12などに拡大。最大12 |
| `keepRoomCountMin/Max` | 標準4..12。大型で最大32へ拡大 |
| `outerFacilityCountMin/Max` | 明示時4..32。未指定の160px以上では型別基準8..20を裕福度で調整 |
| `outerFacilityDensity` | 未指定施設数へ掛ける密度。既定2.0、0.5〜3.0 |
| `moatWidthMin/Max` | 2..5 |
| `wallThickness` | 2。指定範囲1..3 |
| `mainRoadWidth` | 3。指定範囲1..5。ブラシの実幅は奇数 |
| `roadExtraEdgeRate` | 0.15。追加道路数はノード数×指定値 |
| `pavingRatio` | 宮殿0.88、その他0.68。指定範囲0..1 |

指定数や部屋寸法が収まらない場合は生成失敗を返す。生成候補が品質を満たさない場合は
`--strict`で失敗になる。既存と同じseedでも、この構造更新前とは配置が変わる。

## Tile semantics

| ID | 意味 |
|---:|---|
| 0 | 未舗装の城内地面 |
| 1 | 訓練・集結の庭 |
| 2 | 庭園 |
| 3 | 城壁・部屋・施設の壁 |
| 4 | 塔・主城の厚い外壁、門楼 |
| 5 | 城内道路 |
| 6 | 橋・門・扉・塔の階段 |
| 7 | 堀・河川 |
| 8 | 貯水槽 |
| 9 | `castle`では生成しない旧外部背景 |
| 10 | 土間・補給の庭・厩舎の床 |
| 11 | 木床の私室・生活/補給施設 |
| 12 | 石床の公的な部屋・塔・厨房・礼拝堂 |
| 14 | 屋外の舗装 |
| 18 | 城壁上の歩行可能な見回り通路 |

10/11/12/14はtownと共通、18はcastle専用の追加タイル。城のPNGと品質評価でも扱う。
現在のRPG-Coboの簡易インポーターは10/11/12/14を通常地面へ読み替える。18を壁上として
立体表示するには下流インポーター側の対応が別途必要であり、本実装では生成PNG/Plan上の
壁上配置と歩行可能性までを保証する。

## Planと品質評価

既存のinclusive矩形region、marker、`regionId` / `regionIndex`、
`parentId` / `parentIndex`を維持する。外形regionは外接矩形であり、斜めの隅の正確な形は
biome配列と`castleDefenseMask`で表す。

`castleDefenseMask`は画像と同じ長さの配列で、最終タイルとは独立した建設時の意図を保存する。

| 値 | 意図 | 許可される最終タイル |
|---:|---|---|
| 0 | 防御帯以外 | 制限なし |
| 1 | 堀 | 7/8 |
| 2 | 外壁 | 3/4/18（18は壁上通路） |
| 3 | 内郭壁 | 3/4 |
| 4 | 許可した堀の橋 | 6 |
| 5 | 許可した外門 | 6 |
| 6 | 許可した内門 | 6 |

品質検査では次を確認する。

- 全markerと、すべての部屋・施設の内部に入口から到達できる。
- 部屋数を扉markerの件数で代用せず、各regionの内部を個別に数える。
- 部屋と施設の扉の両側に、それぞれ内部床と外部の歩行可能セルがある。
- 城壁・内郭壁・堀の全セルに意図しない穴や橋がない。
- 外門を閉じると外側から主城へ到達できない。
- 内郭がある場合、内門を閉じると外郭から主城へ到達できない。
- 主要施設の用途が4種類以上あり、道路網が接続されている。
- 主城が極端に端へ寄らず、庭の未利用部分が過剰に広くない。

`castleCourtyardEmptyRatio`は、施設・主城・庭園・訓練場・補給の庭・道路から
短辺/15（最低4セル）以内の利用範囲を除いた地面の割合。
舗装の有無や地面色だけで空き地を減点/免除しない。

追加診断値は`castleInnerGateCount`、`castleDefenseBypassCount`、
`castleInvalidFacilityDoors`、`castleFacilityRoleCount`、`castleWallWalkCells`、
`castleWatchTowerCount`、`castleMainGateCount`、`castlePosternGateCount`。

## 回帰確認

```powershell
cmake --build build --config Release --target mapimggen castle_layout_tests
.\build\Release\castle_layout_tests.exe

.\build\Release\mapimggen.exe -type castle -w 160 -d 160 -seed 4242 `
  -p castleMode=1 -dir .\tmp\castle_check -out hill --png --report --plan --strict
.\tools\validate_town_castle_plan.ps1 -PlanPath .\tmp\castle_check
```

`castle_layout_tests`は5サイズ×自動/5型×4seedの120ケース、30回の再生成、
長方形での外形多様性40ケース、塔12基と任意の部屋数を含む指定値25ケース、
0.7/2.5の裕福度比較、最大1024までのサイズ・堀幅・壁厚・舗装0/100%を検証する。
192以上の各型では、四隅が型別の単色地形であり、防御帯に誤分類されず、黒い背景がないことも検証する。
故意に堀/外壁/内壁へ橋を作ったケース、内郭への抜け道、閉じた部屋も検出する。
`bat/generate_30_castle_160.bat`から従来どおりseed由来の裕福度で30枚生成できる。
`bat\generate_30_castle_160.bat 2.5`とすると、全30枚を裕福度2.5へ固定し、出力folder名にも
`_wealth_2.5`を付ける。第2引数は外壁防衛力で、例えば
`bat\generate_30_castle_160.bat 2.5 0.4`は裕福だが堀・外壁のない城を30枚生成する。
